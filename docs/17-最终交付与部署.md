- `blueos-workshop-1.0.0-release.apk`：versionCode 10，正式签名，证书 SHA-256 `0f885077fb73915c0256b283d90eac28d2e0a08e27d374ba1ae956f615620482`。`debug.apk` 为不同包名且仅 Debug 允许 http。旧 0.1.0 只保留历史。

- `DELIVERY.json` 记录精确 Git 修订和 America/Los_Angeles 时间；`SHA256SUMS.txt` 包括所有交付文件。

复现（仓库根目录）：

```sh
npm ci --no-audit --no-fund
npm run typecheck && npm run lint && npm test
python3 scripts/test-package-delivery.py
NITRO_PRESET=node-server node scripts/with-app-env.mjs npx vite build
npm run build:android-web
# JDK17, SDK34, Gradle8.9；BLUEOS_KEYSTORE_PROPERTIES 指向仓库外正式配置
cd android && gradle testDebugUnitTest assembleDebug assembleRelease --no-daemon && cd ..
ANDROID_HOME=/path/to/sdk RPK_SAMPLE_DIR=/path/to/officially-built/rpk-sample \
  python3 scripts/package-delivery.py /path/to/deliverables
cd /path/to/deliverables && sha256sum -c SHA256SUMS.txt
```

打包器仅 Git 跟踪源码（不捡未跟踪数据），强制 apksigner 验证 Release，不用 unsigned 替代；ZIP CRC 和路径审计排除 node_modules、签名私钥、.env、备份等。打包器不负责从配置自动识别所有可能写错的秘密，仍需人工 secret review。Android source 包为保证共享模块可重建，会同时含完整仓库其他源码；不是仅 Java 宿主。

## 独立部署包启动

需要 Node >=24、PostgreSQL >=14、npm、Linux。先在内网演练，再配置生产域名/HTTPS。Redis 目前**没有接入**：任务队列、积分事务、幂等和限流落 PostgreSQL，不把不存在的 Redis 部署列为已完成。

```sh
unzip blueos-work-server-deploy.zip
cd blueos-work-server-deploy
npm ci --omit=dev --no-audit --no-fund
cp .env.example .env
chmod 600 .env
# 本地编辑 .env：DATABASE_URL、BETTER_AUTH_SECRET（强随机）、BETTER_AUTH_URL（真实 https origin）、
# BOOTSTRAP_ADMIN_EMAIL（指定自己注册的管理员邮箱），PORT / HOST；不要把密钥写到命令行历史。
set -a; . ./.env; set +a
npm start   # 执行迁移后启动 .output/server/index.mjs
PORT="$PORT" sh scripts/healthcheck.sh
```

环境模板的 CHANGE_ME/空值不是生产配置。首次初始化期间先防火墙只允许管理员连接：注册指定管理员并核对角色、禁用公开注册或设置合适策略后再开放。不要把“空库首个调用者自动管理员”的引导路径公开给互联网抢占。DB 不开公网，最小权限应用账号；轮换 auth secret 会使已有会话失效，安排窗口。

Nginx：按 `deploy/nginx.conf.example` 改 server_name、HTTPS 证书路径、上游端口和上传限制，测试配置后部署；模板不是已签发 HTTPS。正式 APK 只连 https。生产进程用 systemd/同等守护（专用低权限账号、EnvironmentFile 0600、Restart=on-failure、限制只读系统/可写数据目录），不可用开发服务器长期运行。Docker/compose 文件存在，但 box 没 Docker，**镜像/容器运行未验证**。

## Worker（必须 fail closed）

API 与 Worker 分开进程，工具链安装在独立目录，release RPK pem 在仓库外仅 Worker 用户可读。配置 `BLUEOS_TOOLKIT_DIR`、`BLUEOS_RPK_SIGN_DIR`、`DATABASE_URL`，后台开启构建并发/开关。

必须支持 Linux user/mount/network namespace 与 bubblewrap 临时 overlay。`BUILD_SANDBOX=auto` 和 `bwrap` 都强制启动探测，缺失/拒绝/超时/网络泄漏直接非零退出，不连接 DB、不心跳、不领取任务；`none` 永远拒绝。编译只允许 bwrap 分支，运行中隔离启动失败按失败释放预扣。Docker 内网不是替代。详见 docs/12；不要通过 privileged 或裸跑规避。

## 监控、容量和安全

`HEALTH_URL=http://127.0.0.1:<PORT>/api/health sh scripts/healthcheck.sh`：非 2xx/超时失败，检查 DB 连通。用现有监控平台每分钟从可信网络执行并对失败告警；这里只交付脚本/建议，**没有偷偷创建后台定时任务或外部告警服务**。

同时监控：Worker 心跳新鲜度（build_workers.seen_at）、任务失败/长时间排队、预扣额度、磁盘/DB 容量与备份新鲜度。日志写到受限 journald/现有日志系统，保留任务脱敏日志但不记录密码/令牌/数据库 URI/签名私钥；避免把 .env 或原始 auth 请求体发到公共日志。

资产/RPK 当前存 DB（含 base64 JSON 下载），大流量/大资产需要评估对象存储和流式下载；没有做生产压力/SLO/渗透认证。

## 备份恢复、升级回滚

```sh
# DATABASE_URL 已从 0600 文件读入；备份为私有 0600，包含真实用户/会话数据
sh scripts/backup-db.sh
# 复制到加密、受限、异地备份位置需单独授权；本轮没有自动外传。
# 演练仅恢复到 NEW EMPTY TEST DB，绝不覆盖现有生产数据：
DATABASE_URL=<new-empty-test-db> sh scripts/restore-db.sh <backup.dump>
```

restore 使用 `--clean --if-exists --single-transaction`，会清目标同名对象！生产恢复必须停写、确认目标与备份、保留恢复前快照，并取得具体恢复授权。脚本成功不等于业务校验成功；核对迁移表、用户/工程/额度/任务行数与样本校验，再启动并测登录/权限。

升级：记录旧 Git SHA、APK/服务器包哈希 → 停写/维护模式 → 备份 DB 与配置（密钥单独安全备份）→ 新包在独立目录执行迁移 → 内部 health/API smoke → 切换上游/进程 → 观察错误/队列。失败先停新 Worker，不要双版本消费；应用回滚只切旧代码且先判断新 schema 是否兼容。数据库不盲目 down migration；不兼容时根据已演练备份恢复并接受已确认的数据回退窗口。Android 升级必须同包名/证书，降 versionCode 不是常规回滚策略。
