### 1.1 技术栈（实际读取 package.json 与代码）

| 层 | 实际使用 | 说明 |

### 1.3 服务端运行方式（实测）

| 项 | 实际情况 |
| --- | --- |
| 启动 | `npm run dev` → `vite dev --host 0.0.0.0 --port 8080` |
| 端口 | **写死**：`package.json` 的 dev 脚本 8080，`vite.config.ts` 中 dev 8080、preview 8081（strictPort）。`Dockerfile` 用 `${PORT:-8080}` 传给 `vite preview` |
| 数据库 | `DATABASE_URL` 有值 → `pg` 连接池；无值 → 内存 PGLite（**重启丢数据**，不能用于生产） |
| 迁移 | 生产：`npm run build` 末尾 `node scripts/migrate.mjs`；PGLite：启动时自动执行 |
| 认证 | Better Auth，邮箱密码开启；第一个调用 `me` 的账号自动成为 `super_admin` |
| 环境变量 | `DATABASE_URL`、`BETTER_AUTH_SECRET`、`BETTER_AUTH_URL`、`GROK_AUTH_ISSUER/CLIENT_ID/CLIENT_SECRET`、`VITE_AUTH_ENABLED`、`GROK_PROJECT_ID`、`PORT`。**仓库没有 `.env.example`**（docs/07 说已增加，实际不存在） |
| 未设 `BETTER_AUTH_SECRET` | 每次进程启动随机生成密钥，重启后全部会话失效 |
| 健康检查 | `GET /api/health` → `{"ok":true,"service":"blueos-workshop"}`（不检查数据库） |
| 统一 API | `POST /api/v1/platform`，body `{action, payload, client}`，bearer token 认证；网页走 TanStack server function，同一个 `dispatch` |

### 1.5 平台业务（logic.server.ts）

共享接口 19 个：`me listProjects syncProject deleteProject generate exportBundle listJobs downloadJob requestBuild market install redeem listOrders createOrder developerApply mySubmissions submitComponent ledger releaseCheck`。
后台接口 27 个：`adminOverview adminUsers adminUser adminSetStatus adminSetRole adminGrantQuota adminGrantMembership adminGrantComponent adminSetDeveloper adminComponents adminSetComponent adminSubmissions adminReview adminPlans adminSavePlan adminCreateKeys adminKeys adminSetKey adminOrders adminConfirmOrder adminRefundOrder adminJobs adminAnnouncements adminSaveAnnouncement adminConfig adminSetConfig adminAudit adminReleases adminSaveRelease`。

- 积分：`quota_accounts(balance, reserved)` + `quota_ledger` 流水；`reserve → commit → release` 用单条条件 UPDATE 实现，**没有数据库事务包裹**（预扣、确认、写流水、更新任务是多条独立语句）。
- 三种积分：`generation`（历史生成）、`build`（RPK）、`export`（工程下载），代码里互不抵扣。新账号三种都是 0。
- 卡密：`BH-XXXX-XXXX`，只存 SHA-256 和提示，明文仅生成时返回；兑换用 `status='unused'` 条件更新防并发（实测 3 个并发兑换只有 1 个成功）。
- 订单：创建 → 待确认 → 管理员确认/取消 → 撤销（refunded）。无自动支付。
- 组件：14 个官方组件 MB001–MB014，授权类型 `public_free/membership/license_key/specific_user/internal/disabled`，后台可改；只有一个 `latest_version`，没有组件 Schema 版本内容。
- 审计：`audit_logs`，后台写操作都记录。

### 1.6 BlueOS 生成器（src/lib/blueos）

- `model.ts`：工程模型（Project/ScenePage/SceneNode/AppAction/AppVariable/AppFunction/TimeBinding）、DSL（`schemaVersion "1.0"`）、校验 `validateDsl`、预览执行 `runActions`（函数调用最多 3 层）。
- `emit.server.ts`：把 DSL 生成蓝河源工程 zip（`src/manifest.json`、`src/app.ux`、`src/pages/<页>/index.ux`、占位 logo），**产物类型 `source_zip`，明确不是 RPK**。
- `bproj.ts`：读取 .bproj（存储式 zip）。
- 实测：生成器输出**不能直接被官方 toolkit 编译**，见第 8 节。

## 4. 空实现与假数据清单

### 4.1 缺陷 / 不符合规则

1. `exportBundle`（logic.server.ts:383）：
   - 用**客户端提交的工程内容**打包，只核对工程 id 归属 → 可以导出从未保存、含未授权组件的工程（实测）。
   - 去重键是提交内容的 SHA-256，`normalizeProject` 在缺 `updatedAt` 时填 `Date.now()` → 相同工程重复下载被**重复扣费**（实测扣 2 次），违反 12.3。
   - 不检查组件授权。
2. `runGeneration` 的「并发限制」实际是「2 秒内成功任务数」，不是并发任务数。
3. 任务行先以 `status='failed', message='处理中'` 插入（没有 queued/running 状态），任务状态不符合 13.2。
4. `adminRefundOrder` 把该用户所有生效会员都结束，不是只撤销该订单对应的会员。
5. `adminSetStatus` 没有层级限制：拥有 `users.ban` 的 admin 可以封禁 super_admin。
6. `build_enabled`、`membership_open` 开关是摆设（没有代码读取）；`createOrder` 不检查 `membership_open`。
7. `/api/v1/platform` 不做请求体大小限制（server function 那边有 500KB 限制），所有业务错误一律 400（权限不足应 403，不存在应 404）。
8. 没有事务：`reserve → 写流水 → commit → 更新任务` 中途失败会留下不一致（例如已扣分但任务未更新）。
9. `docs/07` 声称已增加「环境变量模板」，仓库里不存在 `.env.example`。
10. `.gitignore` 列出了 `migrations/0001..0004.sql` 和 `server/virtual-grok-og-identity.d.ts`，但这些文件已被跟踪 —— 新迁移文件很容易被误忽略。

### 4.2 假数据 / 占位

- 生成器 logo 是程序画的占位 PNG（README 已注明）。
- `migrations/0002` 种子公告「目前只交付源工程」是真实说明，不算假数据。
- 套餐种子（工坊会员 ¥49、工作室 ¥129、普通会员 ¥29、专业会员 ¥199）是迁移里的**示例价格**，可在后台改；上线前需运营确认。
- 未发现伪造「构建成功」的代码：`requestBuild` 固定返回 `unavailable` 且不扣分。

## 8. RPK 工具链调研结论

### 8.1 附件 SDK 内容（eb2396… zip，10.2 MB）

- `2/js/api/**`：蓝河 JS API 的 `.d.ts` 类型（app/notification、appmanager、event、hardware 电池/传感器/显示/定位/振动、media/audio、bluexlink、telephony、network、storage、security、package、window、health、service、bluetooth、util），`js-package.json`：`apiLevel 2, releaseType Beta, version 1.0.0`。
- `2/native/c++/sysroot`：Native C++ sysroot（头文件），`native-package.json` 同样 apiLevel 2 Beta。
- **`2/js/build-tools/blueos-toolkit-1.9.45-beta.44.zip` + 《使用说明文档.md》**：官方 CLI 构建工具 `blueos-toolkit`（命令 `bot init / bot build / bot release`），含 compiler、packager、dsl-mvm、server、debugger、shared-utils 等 9 个 tgz。说明文档原文：「blueos-toolkit是个CLI工具，提供了创建蓝河应用的模版工程和编译打包的功能，使开发者可以在不使用蓝河Studio的情况下，也能完成代码工程的创建和编译打包等工作。」

### 8.2 本次在 Linux 上实测（全部亲自运行）

```bash
mkdir bw-rpk && cd bw-rpk && npm init -y
npm i -D ./dist/blueos-toolkit-1.9.45-beta.44.tgz     # 720 个包，成功
npx bot build                                         # 失败：Cannot find module 'webpack/lib/EntryOptionPlugin'
npm i -D webpack@5.89.0                               # 新版 webpack 5.112 移除了该文件，需锁定旧版
npx bot init watch-demo --watch                       # 生成官方模板
cd watch-demo && bot build                            # 成功
# [LOG] 项目构建启用了内置 debug 签名
# [LOG] 项目构建并生成文件：com.watch.demo.debug.1.0.0.rpk
# dist/watch-round/debug/com.watch.demo.debug.1.0.0.rpk（30 KB）
# 包内：META-INF/CERT、META-INF/build.txt、com.watch.demo.vru、manifest.json、logo.png
bot release                                           # 失败：缺少 release 签名私钥 sign/release/private.pem
```

关键结论：

1. **Linux 无头构建 debug RPK：可行（已实测）。** 需要 Node（实测 v24 可用）+ 锁定 `webpack@5.89.0`。
2. 构建日志有一行 `mac / linux 端暂无 cjson 工具`：某个 JSON 编译步骤在 Linux 上被跳过，产物在手表上能否运行 **待验证**（可能需要 Windows 或 Studio 才有的工具）。
3. **release RPK 需要开发者自己的签名**：`sign/release/private.pem`（+ 证书）。这是用户必须提供的外部条件。
4. **现有生成器输出不能直接编译**（实测）：`bot build` 报 `编译失败：请确认manifest.json中配置的文件路径存在：Home/index`。原因：页面放在 `src/pages/Home/`，但 manifest 路由键写的是 `Home`。按官方文档「key 为 src 目录下页面目录的相对路径」应为 `pages/Home`。手工把键改成 `pages/Home` 后**成功编译出 `com.example.hello.debug.1.0.rpk`**。另外生成器使用 `@blueos.app.appmanager.router` 与 `blueos.window.prompt`，而 1.9.45 模板使用 `system.router` / `system.prompt`；`router.push({uri:"Detail"})` 与路由键 `pages/Detail` 是否匹配 —— 编译通过，**运行待真机验证**。
5. 这个 toolkit 是 2023-12 的 webpack 版（beta）。公开资料显示新版编译工具已改为基于 Vite（来源 4），新旧版本产物与当前手表固件的兼容性 **待验证**。

### 8.3 公开资料（可引用）

1. vivo《构建首个蓝河应用》：官方推荐在 BlueOS Studio 中开发、打包，「release 包需要填写信息生成签名后，再行打包」，产物在 dist 目录。https://developers-watch.vivo.com.cn/reference/quickstart/quick-start
2. vivo《manifest 文件》：`package/name/icon/versionCode/config/router/appCategory` 必填，`designWidth` 建议 466，`router.pages` 的 key 为页面目录名。https://developers-watch.vivo.com.cn/reference/configuration/manifest
3. vivo《文件组织》：路由 key 为「src 目录下页面目录的相对路径」。http://developers-watch.vivo.com.cn/reference/configuration/file-organization/
4. 第三方文章：BlueOS 编译工具基于 Vite（旧版基于 Webpack），也可通过 npm 安装后命令行调用。https://quickapp.lovejade.cn/blueos-app-development-how-to-use-npm/
