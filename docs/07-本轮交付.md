# 本轮实际完成

这不是最终验收通过。下面只记录已经改到仓库里、并且可以核对的部分。

## 已做

- `/duel` 不再是产品页面，打开后回到工程列表。腕上对决素材已删除。
- 工程增加结构化函数、动作触发（点击 / 长按 / 双击 / 滑动）、变量相等条件、时间绑定字段。旧工程读入时补空数组，不会丢页面。
- 网页预览：点击只跑「点击」动作；函数调用最多三层；条件不满足就跳过。时间绑定只在预览里每秒刷新。
- 长按、双击、滑动、自定义函数和循环没有按 BlueOS 手表 SDK 验证，界面写明了这一点。
- Android 客户端改为走 `/api/v1/platform`，不再把说明页当作客户端。登录使用现有 `/api/auth/*`。
- 新增 `GET /api/health`。
- 订单可以在服务端撤销：结束未到期会员，并尽量扣回套餐发放的积分。余额不够时不会扣成负数。
- 登录信息会登记客户端类型到 `client_devices`。
- 增加 Dockerfile、docker-compose、Nginx 示例、环境变量模板和数据库备份脚本。

## 没做，不能勾成完成

- 没有官方 BlueOS SDK，不能编译真实 RPK，也不能在手表上安装验证。申请打包仍返回不可用，不扣 RPK 积分。
- Redis 只在 compose 里预留，业务代码没有使用它。
- 没有独立构建 Worker，没有 CPU 和内存隔离的 RPK 沙箱。
- Android 没有正式发布证书。调试签名只用于安装测试。私钥密码不要当成正式签名。
- 没有真机安装记录，也没有手表运行记录。
- 桌面端没有客户端。
- 支付仍然不是自动到账。

## 端口

- 网页和 API 同一个进程，默认 `PORT=8080`。
- 管理后台是同一个站点的 `/admin`，没有单独端口。
- Postgres 只在 compose 内部使用，不映射到公网。
- Redis 预留，不映射到公网。
