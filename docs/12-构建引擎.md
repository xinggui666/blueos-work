# 构建引擎（阶段 4）

把工程变成能装到蓝河手表上的 RPK。分三层：**原生生成器**（工程 → BlueOS 源工程）、**构建任务**（API 侧状态机 + 积分）、**构建 Worker**（单独的进程，用官方工具链在隔离环境里编译）。

## 1. v2 原生生成器（`src/lib/generator/`）

- 入口：`generateNative(doc)`，生成器版本 `native-2.0.0`。先跑完整的工程校验，有错误直接拒绝，不会出“残缺”的工程。
- **逻辑不丢**：以前的生成器只翻译少数动作，像“计数 +1”这类表达式会被丢掉。现在把网页预览用的同一个解释器（`src/lib/protocol/runtime.ts` + `expr.ts`）用 rolldown 打包成 ES2015（约 23 KB，`watch-runtime.generated.ts`），原样放进 RPK 的 `src/common/engine.js`，工程本身作为数据放进 `project.js`。预览和手表跑的是同一份代码。
  - 打包产物入库并带 SHA-256；CI 用 `node scripts/gen-watch-runtime.mjs --check` 保证它和源码一致。
  - 解释器里不使用 `eval` / `new Function`（单测检查）。
- 生成的源工程结构：

  | 文件 | 作用 |
  | --- | --- |
  | `src/manifest.json` | 包名、版本、页面路由 `pages/<名字>`；只在用到时声明 `blueos.window.prompt`（弹提示）和 `blueos.storage.storage`（变量持久化） |
  | `src/app.ux` | 全局运行时实例；`onShow/onHide` → 恢复/切后台 |
  | `src/common/engine.js` | 共享解释器 |
  | `src/common/project.js` | 工程数据 |
  | `src/common/host.js` | 胶水层：渲染、路由（`router.push/back`）、持久化（键 `bw_<变量>`，JSON）、手势、定时器 |
  | `src/pages/<名字>/index.ux` | 页面模板；组件属性来自运行时状态，事件交给 `handle(id, 事件)` |

- 手势：BlueOS 原生有 `click`、`longpress` 和 touch 事件；双击（350 ms 内两次点击）、滑动（位移 ≥ 30 px）由胶水层用 touch 事件推导。定时器 1 s 或 10 s 一跳，页面隐藏时停止。
- 单测（`native.test.ts`）在模拟的 BlueOS 系统模块里实际运行生成的代码：计数器点击 3 次显示 3 并弹出“到 3 了”，跳页和系统返回同步，持久化变量重启后恢复。

## 2. 构建任务（API）

接口：`requestBuild`、`listBuilds`、`getBuild`、`cancelBuild`、`downloadBuild`（见 `docs/04-接口清单.md` 和 `src/lib/contract/surface.ts`）。

状态：

| 状态 | 含义 | 积分 |
| --- | --- | --- |
| `unavailable` 不可用 | 后台没开构建（`build_enabled`）或没有在线 Worker | 不扣，不预扣 |
| `queued` 排队 | 超过套餐并发数，等前面的任务 | 已预扣 1 |
| `waiting` 等待构建 | 等 Worker 领取 | 已预扣 1 |
| `running` 构建中 | Worker 正在编译 | 已预扣 1 |
| `succeeded` 成功 | 编译成功且产物检查全部通过 | 确认扣除 1 |
| `failed` 失败 | 编译错误、超时、产物检查不过、Worker 掉线 | 退回 |
| `cancelled` 已取消 | 用户取消 | 退回 |

- 积分走 `quota_ledger`：`reserve` → `commit` 或 `release`，每一步都有流水，余额和预扣数一起更新（事务内锁行）。
- 只构建**云端已保存的修订**（修订号 ≥ 1）。同一修订、同一模式、同一生成器已有任务时直接复用，不重复扣分；并发点击只会产生一个任务。
- 构建前检查组件权限（套餐/上架组件），和编辑器一致。
- 有任意在线 Worker 带签名证书时出 release 包，否则出 debug 包。
- Worker 心跳 60 秒内算在线；`running` 任务 180 秒没有心跳判失败并退回预扣（幂等）。

## 3. 构建 Worker（`worker/`）

```sh
# 一次性：把 SDK 里的官方工具链装到固定目录（Worker 编译时不联网）
sh worker/install-toolkit.sh /path/blueos-toolkit-1.9.45-beta.44.tgz /opt/blueos-toolkit
# 运行
DATABASE_URL=postgres://... BLUEOS_TOOLKIT_DIR=/opt/blueos-toolkit \
BLUEOS_RPK_SIGN_DIR=/安全路径/rpk-sign  node worker/build-worker.mjs
```

| 环境变量 | 默认 | 说明 |
| --- | --- | --- |
| `DATABASE_URL` | 必填 | 任务队列就在 Postgres（`FOR UPDATE SKIP LOCKED`） |
| `BLUEOS_TOOLKIT_DIR` | 必填 | 含 `node_modules/.bin/bot` |
| `BLUEOS_RPK_SIGN_DIR` | 无 | 含 `private.pem`、`certificate.pem` 时出 release 包 |
| `BUILD_SANDBOX` | `auto` | `auto` / `bwrap` 都强制隔离探测；bwrap 不可用、超时或网络未隔离就退出，连接数据库和领取任务之前失败。`none` 已禁止 |
| `BUILD_TIMEOUT_SEC` | 300 | 总时长，超时杀掉整个进程组 |
| `BUILD_MEMORY_MB` | 1536 | Node 堆上限 |
| `BUILD_WORK_DIR` | 系统临时目录 | 每个任务一个临时目录，结束删除 |
| `BUILD_POLL_MS` | 2000 | 空闲轮询间隔 |

隔离（bwrap 模式）：`--unshare-all`（没有网络）、系统目录只读、工具链用临时 overlay（工具链会 chmod 自带的 aapt）、只有任务目录可写；`prlimit` 限制 CPU 时间、单文件 200 MB、文件句柄；环境变量清空，不带数据库地址和任何密钥；签名证书只在编译期间复制进任务目录。

产物检查（`worker/rpk.mjs`，不通过就算失败）：大小、zip 结构和路径安全、`META-INF/CERT`、manifest 的包名/版本/debug 标记/页面路由、`<包名>.vru` 文件头 `vivo union file`、所有页面都编进了 vru。源工程 zip 冒充 RPK 会被拒绝（单测）。

Docker：`Dockerfile.worker` + `docker-compose.yml` 里的 `worker` 服务（`--profile build` 启动，只在内部网络，限制内存/CPU/进程数）。**开发机没有 Docker，镜像尚未实际构建验证。** 容器必须显式满足 bwrap 的用户命名空间/overlay 要求，不满足时拒绝启动（不再退回 `none`）；建议在专用构建主机用 systemd 直接跑 Worker。

## 4. 实测

`node scripts/e2e/build-rpk.mjs`（真实 Postgres + 官方工具链 1.9.45-beta.44 + bwrap）9 步全部通过：后台关闭/无 Worker → 不可用不扣分；积分不足 → 拒绝；3 个并发请求 → 1 个任务 1 次预扣；真实 release 构建成功并确认扣除；下载的 RPK 哈希一致，vru 里有 `count + 1` 和两个页面；同修订复用；超时 → 失败并退回；排队中取消 → 退回，重复取消 409；别人的任务 404。

### 隔离部署要求（Stage 5 安全修正）

Worker 必须运行在支持 Linux user/mount/network namespace 的主机，安装支持 `--tmp-overlay` 的 bubblewrap，并允许该进程创建用户命名空间。`prlimit`（util-linux）和工具链均须可用。只读系统目录、临时工具链 overlay、私有 /tmp 和 /dev、断网是强制要求。

`BUILD_SANDBOX=auto` 现在与 `bwrap` 同样 fail closed。探测失败时 Worker 非零退出，不连接数据库、不发布心跳、不领取任务，不会退回宿主机裸跑。运行中 bwrap 失败则任务失败并释放预扣。不得用 `none`、Docker 内网或资源限制冒充 namespace 沙箱。生产部署必须先在目标主机验证 `node worker/build-worker.mjs --once`，并检查日志 `沙箱 bwrap`。普通 Docker 的默认 seccomp/userns/overlay 权限可能不够；不要盲目添加 privileged。优先独立构建主机，按最小权限配置 namespace 和 overlay 支持。当前 compose Worker 镜像仍未实测；它若不满足要求会拒绝启动，不能当作开箱即用生产方案。

自动测试：`node --test worker/sandbox.test.mjs` 覆盖缺失 bwrap、权限拒绝、超时、网络可连、禁止 none 和成功探测。
