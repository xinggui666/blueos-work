# 如何运行

网站和服务器在同一个工程里。

1. 安装依赖后执行 `npm run dev`。
2. 数据库迁移随构建执行：`npm run db:migrate`。
3. V3不再将首个注册账号自动提升管理员。先限制网络/注册，建立指定账号，再由运维执行 `node scripts/bootstrap-admin.mjs --user-id <指定账号ID> --email <该账号邮箱>`。环境中必须安全注入DATABASE_URL；勿把连接串写入报告。可选运行时引导必须同时绑定BOOTSTRAP_ADMIN_USER_ID和BOOTSTRAP_ADMIN_EMAIL，邮箱单独无效。见 `docs/v3/phase-1-report.md`。
4. 不要把密钥写进仓库。部署时由平台注入数据库和登录配置。

客户端源码包不是一份可以脱离服务器单跑的安装包。它是网页编辑器的源码，请求发到上面的共用接口。Android 和桌面端以后也调用这组接口。

## RPK 构建 Worker（可选，阶段 4）

不跑 Worker 时，网站照常可用，发起 RPK 构建会显示“不可用”且不扣分。要真正出 RPK：

1. 后台开启 `build_enabled`。
2. 安装官方工具链：`sh worker/install-toolkit.sh /path/blueos-toolkit-1.9.45-beta.44.tgz /opt/blueos-toolkit`（tgz 来自蓝河 SDK，不随仓库分发）。
3. 启动：`DATABASE_URL=... BLUEOS_TOOLKIT_DIR=/opt/blueos-toolkit [BLUEOS_RPK_SIGN_DIR=/安全路径/rpk-sign] npm run worker:build`。
4. 端到端自检：对一个**空的测试库**启动服务后，执行 `DATABASE_URL=（同一个库） BLUEOS_TOOLKIT_DIR=/opt/blueos-toolkit API_BASE=http://localhost:端口 node scripts/e2e/build-rpk.mjs`。脚本会注册测试账号、改后台开关、发积分，不要对正式库运行。

环境变量、隔离方式和状态说明见 `docs/12-构建引擎.md`。

## V3 一次性会员额度生效（迁移 0009）

升级前先做数据库备份并保留旧应用产物；停 API/Worker 写入，执行 `npm run db:migrate` 到 0009，再同时更新 API/Worker。不得只更新应用而遗漏函数。旧行保守标为已发放，不自动补发/追缴历史额度。详见 `docs/v3/phase-1-followup-report.md` 迁移/回滚段。

- 新会员段保存 `pending`，到数据库 `starts_at` 时才应发一次性 `generation`、`export`、`build + bonusBuild`；退款前置撤销未来段后永不发放。周期 `monthlyBuild`/`dailyBuild` **没有实现，不作为一次性发放**。
- 用户 API 在业务计费前懒激活；运行中的安全 Worker 每轮调用同一数据库函数。无需为发放额度而关闭沙箱或启动不安全 Worker。
- 无 Worker 或需降低离线延迟时，在仓库/部署包目录由运维调度器每分钟运行 `node scripts/activate-membership-credits.mjs`；安全注入 `DATABASE_URL`，不要把凭据放命令行或日志。该脚本**不会自动安装 cron**。一次最多处理 500 段，成功只输出计数；大队列需重复运行并监控滞后。
- 权益应在时间边界生效，余额实际入账在下一次 API/Worker/运维调度事务时完成，不能承诺无调度器的精确零延时。停机恢复时未撤销的到期一次性额度会补入（即便会员段已结束）；这里明确采用一次性余额不随到期清零的规则。
- 发现无效 snapshot 应报警并人工修复/复核，事务整批回滚，不跳过/猜测权益。旧未来段若历史已提前发放，本迁移不自动追回，需要对账；退款沿用原 grant 流水及差额记录。
- 退款不自动把后续已排队会员段的原 `starts_at` 前移，可能留下空档；周期发放、自然月/时区/结转及续费退款时间轴管理仍待独立业务闭环。durationDays 仍按固定 24 小时计算，不等于自然月。
