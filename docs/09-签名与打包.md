# 签名与打包（Android APK / 蓝河 RPK）

所有私钥、证书和密码**只放在仓库外**，绝不提交。`.gitignore` 已忽略 `keystore.properties`、`*.jks`、`*.keystore`、`*.pem`、`sign/`。

## 1. Android 正式签名

`android/app/build.gradle` 按以下顺序读取签名配置，都没有时 release 产物为未签名包（`app-release-unsigned.apk`），**不会回退到调试证书**：

1. 环境变量 `BLUEOS_KEYSTORE_FILE` / `BLUEOS_KEYSTORE_PASSWORD` / `BLUEOS_KEY_ALIAS` / `BLUEOS_KEY_PASSWORD`
2. 环境变量 `BLUEOS_KEYSTORE_PROPERTIES` 指向的仓库外属性文件（推荐）
3. `android/keystore.properties`（已忽略，本地用）

属性文件格式：

```properties
storeFile=/绝对路径/blueos-release.jks
storePassword=...
keyAlias=blueos-release
keyPassword=...
```

生成新密钥（只做一次，丢失后无法更新已发布的应用）：

```sh
keytool -genkeypair -keystore blueos-release.jks -storetype PKCS12 -alias blueos-release \
  -keyalg RSA -keysize 4096 -validity 10000 -dname "CN=BlueOS Workshop, O=..., C=CN"
chmod 600 blueos-release.jks
```

构建（JDK 17 + Android SDK platform 34 / build-tools 34，Gradle 8.9）：

```sh
cd android
BLUEOS_KEYSTORE_PROPERTIES=/安全路径/keystore.properties gradle assembleRelease
# 产物：app/build/outputs/apk/release/app-release.apk
apksigner verify --print-certs app/build/outputs/apk/release/app-release.apk
```

CI（`.github/workflows/android-apk.yml`）目前只产出未签名 release 包和调试包；如需 CI 出签名包，把 keystore（base64）和密码配置为仓库 Secrets，再在工作流里解码到临时文件并设置上述环境变量。

> 当前正式密钥由开发代理生成，存放在开发机 `/workspace/secrets/blueos-work/`（权限 600），证书 SHA-256 指纹见交付说明。请尽快把 keystore 和密码文件备份到你自己的安全位置。

## 2. 蓝河 RPK 打包

依据：蓝河官方文档《快速入门》打包一节（https://developers-watch.vivo.com.cn/reference/quickstart/quick-start/ ）说明 release 包需要“填写信息生成签名后再打包”，产物在 `dist/`；表盘工程结构文档（https://developers-watch.vivo.com.cn/reference/extend/watchface/ ）给出签名文件位置 `sign/certificate.pem`、`sign/private.pem`。同源的命令行工具（小米 Vela aiot-toolkit 文档 https://iot.mi.com/vela/quickapp/en/content/tutorial/toolkit.html ）给出生成签名的方式：

```sh
openssl req -newkey rsa:2048 -nodes -keyout private.pem -x509 -days 3650 -out certificate.pem
```

命令行编译使用蓝河 SDK 包中的 `blueos-toolkit`（命令名 `bot`，本次实测 1.9.45-beta.44），需配 `webpack@5.89.0`：

```sh
BLUEOS_TOOLKIT_TGZ=/path/blueos-toolkit-1.9.45-beta.44.tgz \
BLUEOS_RPK_SIGN_DIR=/安全路径/rpk-sign \
sh scripts/build-rpk.sh 导出的源工程.zip 输出目录
```

实测（Linux x64，Node 24）：工坊生成器导出的示例工程**无需手改**即可编出 `com.example.hello.debug.1.0.rpk` 和 `com.example.hello.release.1.0.rpk`（release 包含 `META-INF/CERT`）。尚未在真机上安装验证；上架时用于签名的证书需与开放平台登记的一致。
