# 统一工程协议 v2（阶段 2）

网页工坊、服务端、Android、未来桌面端、预览器、生成器和 `.bproj` 共用同一份结构化工程数据。

| 内容 | 位置 |
|---|---|
| 结构定义（zod，唯一来源） | `src/lib/protocol/schema.ts` |
| JSON Schema（给 Android/桌面端/第三方） | `docs/protocol/project.schema.json`（`npm run protocol:schema` 生成，CI 用 `protocol:check` 防止过期） |
| 语义校验器 | `src/lib/protocol/validate.ts` |
| 表达式语言 | `src/lib/protocol/expr.ts` |
| 执行语义（预览/调试/测试共用解释器） | `src/lib/protocol/runtime.ts` |
| 版本迁移 | `src/lib/protocol/migrate.ts` |
| `.bproj` v2 读写与校验 | `src/lib/protocol/bproj.ts`、`zip.ts` |
| 网页编辑器模型适配 | `src/lib/protocol/editor.ts` |
| 服务端存储/修订/冲突 | `src/lib/platform/projects.server.ts`、`migrations/0005_protocol.sql` |
| 测试 | `src/lib/protocol/protocol.test.ts`（33 项）、`scripts/api-smoke.mjs`（协议部分 9 项） |

## 1. 文档结构

```text
ProjectDoc
├─ format = "blueos-workshop-project", schemaVersion = 2
├─ project      id、名称、应用名、包名、createdAt、updatedAt、revision（服务端修订号）
├─ manifest     设备形态、designWidth=466、画布、versionName/Code、sdk{toolkit, verified}
├─ startPageId、navigation
├─ pages[]      id、name（RPK 页面目录名）、title、background、components[]（数组顺序=图层顺序）
│   └─ component  id、type、version（固定组件版本）、name、layout{x,y,w,h,rotation}、locked、hidden、props
├─ variables[]  id、key、type(string|int|float|bool|array|object|datetime)、default、scope(global|page|component)、ownerId、persist
├─ events[]     id、enabled、trigger、condition(表达式)、throttleMs、actions[]
├─ functions[]  id、name、params[{name,type,default}]、returnType、locals、body[]、version
├─ timers[]     id、kind(countdown|stopwatch)、durationSec
├─ bindings[]   id、componentId、prop、source{variable|time|expr}、format、refresh(change|second|minute)
├─ assets[]     id、kind、path(assets/...)、sha256、bytes、mime
└─ dependencies[] type、componentId、version（由组件实例计算，校验一致性）
```

所有事件、动作、函数、变量、绑定都有唯一 ID（全工程唯一），便于调试定位和迁移。

### 触发器
- 组件：click、longPress、doubleClick、swipeStart/swiping/swipeLeft/Right/Up/Down、touchStart/End、change
- 页面：load、show、hide、exit
- 时间：everySecond、everyMinute、everyHour、at(HH:mm)、dateChange、weekChange、timerEnd；可用 `pageId` 限定只在该页面可见时运行（省电）
- 变量：change、equals、condition、enterRange、leaveRange
- 系统：appStart、appResume、appBackground

除 click 外的组件手势在校验时给出“需要真机验证”警告（规格 7.2/11.3），网页模拟不代表手表支持。

### 动作
navigate、back、toast、show、hide、toggle、setProp、setVar、setLocal、call（参数、返回值写入变量或局部变量）、if/else、repeat（≤100 次）、forEach、return、startTimer/stopTimer/resetTimer、log。

### 可绑定/可修改属性
只允许 `BINDABLE_PROPS` 中列出的属性（文本、颜色、进度、开关等）以及所有组件的 `visible`（布尔）。绑定和赋值都做类型检查。

## 2. 表达式语言
- 字面量（数字、"文本"、true/false/null、[列表]）、变量名、`+ - * / %`、比较、`&& || !`、`?:`、`a[i]`、`a.b`。
- 白名单函数：时间（now/year/…/weekday/formatTime/formatDuration/addMinutes/diffSeconds）、转换（str/int/float/bool/round/floor/ceil/abs/min/max/clamp/percent）、文本（len/upper/lower/concat/substr/padStart/contains）、列表（list/push/at/sum/join）、if。
- 时间格式：`YYYY MM DD HH hh mm ss A(上午/下午) W(星期)`。
- 手写解析器，**不使用 eval / Function**；长度 ≤500、节点 ≤200、嵌套 ≤24、求值步数 ≤5000；除零、类型错误、未知变量/函数都报错。

## 3. 执行规则（runtime.ts）
1. 同一触发的事件按数组顺序执行；事件内动作按顺序执行。
2. 动作出错：记录错误（含动作 ID），该事件后续动作停止，其他事件不受影响。
3. 每次外部触发最多 2000 个动作步；函数调用深度 ≤8；变量连锁触发 ≤4 层（超过记录警告并停止连锁）。
4. 函数之间的循环调用在校验阶段直接拒绝。
5. `throttleMs` 防重复触发。
6. 跳转：当前页 hide → 新页 load（首次）→ show；返回：hide → exit → 上一页 show。
7. 隐藏的组件和非当前页面的组件不响应交互。

## 4. 版本迁移
`migrateToCurrent(input)` 识别并迁移：
- `v1-editor`：早期网页工坊 Project（节点上的动作、`$变量` 文本、时间绑定）→ 事件、if 条件、绑定；
- `v1-dsl`：生成器 DSL 1.0 → v1-editor → v2；
- `future`：更新版本的工程，明确拒绝（不崩溃）。

服务端读取旧数据时自动迁移（旧工程永远能打开），下次保存时以 v2 写回。新增版本时追加 n→n+1 步骤，不删除旧步骤。

## 5. 修订与冲突（规格 4.3）
- 每次**内容变化**的保存形成不可变服务端修订（`project_revisions.source='save'`，含完整 doc 和 SHA-256）；内容不变不增加修订。
- 客户端保存时带 `baseRevision`。云端已有更新修订且内容不同 → 冲突：
  - Android/接口：`saveProjectDoc` 返回 **409**，带 `serverRevision` 和 `serverDoc`；
  - 网页：`syncProject` 返回 `{conflict:true, serverProject}`，网页把云端版本作为主版本，本机内容另存为“（本机冲突副本）”。
- 网页启动合并：用本机记录的“上次同步内容”判断本地是否改过；两边都改过时保留双方。
- 保存只要求结构合法；语义问题随结果返回（草稿可以暂时不完整），构建前必须全部通过。

## 6. `.bproj` v2
```text
manifest.json  format=bproj, version=2, schemaVersion, projectId, revision, contentSha256,
               files{project.json/README.txt: sha256+bytes}, dependencies, officialBuild=false
project.json   ProjectDoc
README.txt     说明（不是源码、不是 RPK）
```
导入流程：ZIP 安全检查（路径穿越、条目数、大小、CRC，支持 deflate）→ 文件 SHA-256 → 内容摘要 → 版本识别与迁移 → Schema 与语义校验 → 预览（页面/组件/事件/函数/依赖数量）。
- 校验失败拒绝导入；导入总是**新建工程**，绝不覆盖已有工程。
- 重复导入（同一账号、同一内容摘要）返回已有工程（`duplicate`），`mode=copy` 时导入为副本。
- 旧版工程包（只有 project.json）按旧格式迁移导入，并提示没有校验信息。

## 7. 接口（`POST /api/v1/platform`）
| action | 说明 |
|---|---|
| `getProjectDoc {projectId, revision?}` | 读取当前或历史修订的协议文档、修订号、内容摘要、语义问题 |
| `saveProjectDoc {doc, baseRevision?}` | 保存协议文档；冲突 409 |
| `listRevisions {projectId}` | 修订列表（来源、客户端、摘要） |
| `validateProject {doc}` | 迁移 + 校验，只返回问题，不保存 |
| `previewImport {fileBase64}` | `.bproj` 导入预览 |
| `importBundle {fileBase64, mode?}` | 导入为新工程 |
| `syncProject {project}` | 网页编辑器格式（兼容旧客户端），内部转换为协议 |
| `exportBundle {projectId}` | 导出 `.bproj` v2（计费规则不变） |

## 8. 已知限制
- 网页编辑器 UI 目前只能直接编辑 v1 能表达的部分（点击动作、简单变量、无参函数、时间文本）；其余协议内容（条件事件、带参函数、计时器、表达式绑定等）在网页中原样保留，阶段 3 提供可视化编辑。
- 生成器（emit）仍从 v1 DSL 生成，阶段 4 改为直接消费协议并把事件/函数编译为 UX 代码。
- 组件 `componentId` 目前都是 `builtin`；商城组件版本固定在阶段 3/4 接入。
- 内容摘要算法变化后，旧的 `.bproj` 下载幂等记录不再命中：升级后首次重新下载同一工程会再扣一次工程下载积分。
